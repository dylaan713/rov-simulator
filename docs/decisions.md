# Decision log

Decisions made while building the simulator, with the alternative that was rejected. All entries below were made during M0.

| Date | Decision | Why | Rejected alternative |
|---|---|---|---|
| 2026-11-07 | Python 3.12 (Homebrew), not the system Python | `/usr/bin/python3` is 3.9.6 and NumPy 2.x needs 3.10 or newer | Pin NumPy 1.26 to stay on system Python; would start a project due 2027-01-31 on an end-of-life interpreter |
| 2026-11-07 | Hand-written fixed-step RK4, not `scipy.integrate.solve_ivp` | Writing the integrator is an M0 teaching goal, and a fixed step makes the step-size study possible. SciPy stays in the dependencies for later milestones | `solve_ivp`: its step is chosen adaptively and hidden, so the convergence study would be meaningless |
| 2026-11-07 | Fresh water, rho = 1000 kg/m^3 | The proving ground is a Florida sinkhole fed by the Floridan aquifer, not the sea | 1025 kg/m^3 seawater: overstates buoyancy by 2.5% and quietly biases every later buoyancy budget |
| 2026-11-07 | Added mass deferred to M2 | M0 targets integration, terminal velocity and step-size behaviour. Added mass changes the transient but not terminal velocity, so M0's validation is exact without it. Stated in the module docstring so it cannot read as an oversight | Including added mass in M0 |
| 2026-11-07 | Approach A's real drag coefficients deferred to M2; M0 uses a declared placeholder body | The design claimed M0 would produce the drag model that `pc1` needs. It cannot: no CAD or hull geometry exists, `pc1` needs a design speed that is still TBD (it was to be set at the missed PDR), and `pc1` is Dylan's own calculation under the mentor-only agreement the design leaves in force for hardware. M0 validates the model and integrator, not the vehicle | Inventing plausible coefficients: a simulator that looks specific to this vehicle while being specific to nothing |
| 2026-11-07 | `src/` layout with an editable install | Tests import the package as a consumer would, so no test manipulates `sys.path` | Flat layout: tests can pass against the working directory instead of the installed package |
| 2026-11-07 | Asymmetric parameter validation: `mass` and `fluid_density` strictly positive; `volume`, `reference_area`, `drag_coefficient` may be zero, never negative | Zero drag and zero volume are legitimate limiting cases the validation suite uses; zero mass is not a body | Uniform strictly-positive rule: tidier, but makes the infinite-terminal-velocity test impossible to write |
| 2026-11-07 | `integrate` raises on a reversed time span | The first version silently returned only the initial state when `t_end < t_start`. A simulator that answers a nonsensical question with a plausible-looking array is the failure mode this project exists to avoid. Beyond what the plan asked for; added by coordinator ruling | Return a one-sample trajectory |
| 2026-11-07 | Compute `z(t)` as `(w_t^2/a0)*(logaddexp(x,-x) - ln 2)` | Algebraically identical to `ln cosh x`, but `cosh` overflows a double above x = 710, so the plain form returned `inf` for t beyond about 320 s on the reference body (AI-assistance log, entry 3) | `(w_t^2/a0)*ln cosh x` |
| 2026-11-07 | Work isolated on a branch, not a git worktree | The repository was minutes old with no other work in flight; a branch is sufficient and keeps files where Dylan is looking | Git worktree |
